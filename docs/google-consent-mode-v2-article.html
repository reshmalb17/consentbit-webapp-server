Google Consent Mode v2

How ConsentBit passes your visitors' consent choices to Google tags, what each setting does, and how to set up basic or advanced consent mode.

What Consent Mode is

In Google's words, consent mode lets you communicate your users' cookie or app identifier consent status to Google. Tags adjust their behavior and respect users' choices.

When a visitor makes a choice in the ConsentBit banner, ConsentBit sends that choice to your Google tags (Google Analytics 4, Google Ads, Floodlight and Google Tag Manager) through Consent Mode. You don't need to write any Consent Mode code yourself.

For Google's full explanation, see About consent mode and Consent mode overview.

Consent Mode is a way to pass consent choices to Google tags. Deciding which consent your website needs to collect, and from whom, is up to you and your legal advisers.

Consent types

Consent Mode uses the consent types below. The descriptions are Google's. The right-hand column shows which ConsentBit banner category controls each one.

Consent typeDescription (Google)Set by ConsentBit category
ad_storageEnables storage, such as cookies (web) or device identifiers (apps), related to advertising.Marketing
ad_user_dataSets consent for sending user data to Google for online advertising purposes.Marketing
ad_personalizationSets consent for personalized advertising.Marketing
analytics_storageEnables storage, such as cookies (web) or device identifiers (apps), related to analytics, for example, visit duration.Analytics
functionality_storageEnables storage that supports the functionality of the website or app, for example, language settings.Preferences
personalization_storageEnables storage related to personalization, for example, video recommendations.Preferences
security_storageEnables storage related to security such as authentication functionality, fraud prevention, and other user protection.Always granted (strictly necessary)

IAB TCF banner: if you use the ConsentBit IAB TCF banner, the advertising consent types are based on the visitor's TCF choices for Google (vendor 755) and the related TCF purposes. ConsentBit also sets Google's enableAdvertiserConsentMode flag, so Google tags can read ad_storage, ad_user_data and ad_personalization directly from the TC string. analytics_storage is sent through Consent Mode.

Default and update commands

ConsentBit sends two kinds of Consent Mode commands for you:

  • Default (gtag('consent', 'default', …)): the consent status your Google tags use before the visitor has made a choice. ConsentBit sends it as soon as its script loads, before your Google tags run. By default, every consent type is denied except security_storage.
  • Update (gtag('consent', 'update', …)): sent every time a visitor makes or changes a choice in the banner, and on later page views for visitors who already chose.

Where you choose to show a US opt-out banner (CCPA mode), the default reflects that opt-out model: consent types start as granted unless the visitor opts out or their browser sends a Global Privacy Control signal. With the script install, in regions where you have chosen not to show a banner, ConsentBit grants consent. With Google Tag Manager, set the defaults for those regions in the ConsentBit CMP template's region table.

Basic and advanced consent mode

Google describes two ways to implement consent mode:

  • Basic consent mode: "When you implement consent mode in its basic version, you prevent Google tags from loading until a user interacts with a consent banner."
  • Advanced consent mode: "When you implement consent mode in its advanced version, Google tags load when a user opens the website or app."
Basic consent modeAdvanced consent mode
Google tags before consentBlocked until the visitor interacts with the consent banner.Load when the page opens, with the default consent status.
Data sent before consentNone.While consent is denied, Google tags send cookieless pings instead of storing cookies.
After the visitor choosesIf the visitor consents, tags load and receive the consent status. If not, tags stay blocked and no data is sent.Tags follow the visitor's choice right away.
ModelingGoogle uses a general model.Google can use cookieless pings for advertiser-specific modeling.

For details, see Google's About consent mode.

Set up advanced consent mode

Advanced consent mode is ConsentBit's default. You don't need to change any settings.

Script install (Webflow app, Framer, or any website)

Put the ConsentBit script first in your page's <head>, then your Google tag as normal:

<head>
  <!-- 1. ConsentBit: first -->
  <script id="consentbit" src="https://manager.consentbit.com/consentbit/YOUR-SCRIPT-ID/script.js"></script>

  <!-- 2. Google tag: after ConsentBit, unchanged -->
  <script async src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
  <script>
    window.dataLayer = window.dataLayer || [];
    function gtag(){dataLayer.push(arguments);}
    gtag('js', new Date());
    gtag('config', 'G-XXXXXXXXXX');
  </script>
</head>

ConsentBit sends the default before the Google tag runs, and an update whenever the visitor chooses.

Google Tag Manager

  1. Add the ConsentBit CMP tag template to your container, with the Consent Initialization - All Pages trigger. Don't also paste the ConsentBit script into your page.
  2. Optionally, set default consent states per region in the template's region table.
  3. Leave your Google tags (Google Analytics, Google Ads, Floodlight) on their usual triggers. They have built-in consent checks and follow the consent status automatically.

Set up basic consent mode

In basic mode, ConsentBit keeps your Google tags blocked until the visitor consents. ConsentBit still sends the default and update commands.

Script install (Webflow app, Framer, or any website)

Mark both parts of your Google tag with type="text/plain" and a data-consentbit-category attribute. ConsentBit loads them only after the visitor consents to that category:

<head>
  <!-- 1. ConsentBit: first -->
  <script id="consentbit" src="https://manager.consentbit.com/consentbit/YOUR-SCRIPT-ID/script.js"></script>

  <!-- 2. Google tag: blocked until the visitor consents to Analytics -->
  <script type="text/plain" data-consentbit-category="analytics" async
          src="https://www.googletagmanager.com/gtag/js?id=G-XXXXXXXXXX"></script>
  <script type="text/plain" data-consentbit-category="analytics">
    window.dataLayer = window.dataLayer || [];
    function gtag(){dataLayer.push(arguments);}
    gtag('js', new Date());
    gtag('config', 'G-XXXXXXXXXX');
  </script>
</head>

Which category to use:

Your Google tagdata-consentbit-category
Google Analytics 4 onlyanalytics
Google Ads or Floodlight onlymarketing
One tag for both Analytics and Adsanalytics,marketing (loads only when the visitor consents to both)

See also Manual script tagging.

Google Tag Manager

  1. Add the ConsentBit CMP tag template with the Consent Initialization - All Pages trigger, as for advanced mode.
  2. Open each Google tag, then go to Advanced Settings → Consent Settings.
  3. Choose Require additional consent for tag to fire and add the consent types the tag needs: analytics_storage for Google Analytics, ad_storage for Google Ads and Floodlight.
  4. Save and publish the container. The tags now fire only after the visitor grants those consent types.

IAB TCF banner

The ConsentBit IAB TCF banner blocks Google tags until the visitor makes a choice, so it runs in basic mode by default. No extra setup is needed.

Switching between basic and advanced

  • Advanced → basic: add type="text/plain" and data-consentbit-category to your Google tag (script install), or turn on Require additional consent for tag to fire (Google Tag Manager).
  • Basic → advanced: remove those attributes, or those additional consent requirements.

In both cases, keep the ConsentBit script (or the ConsentBit CMP template) in place. It sends the default and update commands in either mode.

Check your setup

  • ConsentBit debug mode: open your page with ?consentbit_debug=1. See Debug mode.
  • Google Tag Assistant: open tagassistant.google.com, connect your site, and open the Consent tab. Before any choice, the default should show the consent types as denied. After a choice, you should see an update with the new values.
